# Проверки 0.1.0

## Что реализовано

Отдельный Kotlin APK с ARCore 6DoF, Raw Depth, confidence, RGB JPEG, спариванием, локальными RGB-D-сеансами и передачей с ACK. Windows-совместимый исходный Python-пакет Scan Engine создаёт TSDF, вычисляет облако, обновляет mesh, сохраняет кадры и экспортирует PLY/GLB. Blender-клиент принимает точки, геометрию и траекторию. Android поддерживает три вида предпросмотра геометрии: текущий depth, накопленные точки и каркас. После завершения реконструкции облегчённые результаты сохраняются на телефоне. Проект содержит CI для сборки и тестирования.

## Автоматические проверки

| Сценарий | Проверка |
|---|---|
| Координаты, масштаб и цвет | Синтетическая плоскость Z=1,2 м в камере; глубина переходит в Y=1,2 м в Blender; проверены два цветовых участка и смещения камеры |
| Бракованные измерения | Потеря tracking, несовпадающие timestamps, зеркальная матрица, низкий confidence, повреждённый пакет |
| Протокол | Токен, статус и mesh.updated по WebSocket, pause/resume/stop, SHA-256, ACK, повтор и конфликт ID |
| Очередь | Замедленный worker принимает 8 кадров в очередь, отклоняет следующий с 429; после освобождения тот же кадр принимается |
| Хранение и повтор | Пересоздание ScanManager из записанных пакетов и CLI replay с исправленной позой из JSON |
| Сетевой прогон | Реальный HTTP localhost, 30 из 30 синтетических кадров интегрированы за 3,36 с с паузой 100 мс между загрузками. Последняя интеграция ≈23,4 мс, извлечение mesh ≈10,2 мс. Это замеры на CPU среды для кадров глубины 64×48 |
| Blender 4.3.2 | В фоновом процессе клиент получил 4032 точки, 30 положений камер и mesh. Импорт PLY и GLB дал в обоих случаях 3840 вершин и 7426 треугольников. Проверили координаты плоскости после импорта |
| Phone Rotation | Регистрация исходного аддона 1.4.0 и Scanner одновременно. APK имеют разные applicationId. Вращение и обратное видео требуют телефона |
| APK | Выполнен Gradle assembleDebug, проверены подпись и манифест |

Повтор из `hybrid/`:

```text
python -m pip install -r pc_engine/requirements.txt -r tests/requirements.txt
python -m unittest discover -s tests -v
python -m tests.run_smoke --blender /path/to/blender --output /path/to/fixture
```

Windows x64 использует `requirements-windows.lock`. CLI smoke сохраняет 30 файлов H3S при указании `--output`. Это синтетический набор, пригодный для проверки без телефона. Зависимости для Windows x64/CPython 3.12 разрешены при подготовке пакета. Локальные тесты выполнялись на Linux; запуск Windows предусмотрен в CI.

## Обязательные аппаратные испытания

1. Установить оба APK и оба аддона. На Phone Rotation проверить оси, нулевую ориентацию, сглаживание и поток камеры.
2. На Galaxy A56 5G зафиксировать модель SM-A566*, Android и версию Google Play Services for AR. Открыть приложение, пройти запрос разрешения, убедиться в `Session.isDepthModeSupported(AUTOMATIC)`. На неподдерживаемом устройстве проверить сообщение и недоступность кнопки «Начать».
3. Просканировать матовую размеченную поверхность рядом с линейкой. Проверить, что RGB, depth и confidence принимаются одновременно, никакая ось не отзеркалена и видимые цветовые границы совпадают. Сравнить размеры в PLY и GLB с измерением.
4. Замерить частоту нового Raw Depth, интеграции, ревизий облака и mesh, полную задержку и загрузку Windows-ПК. Сравнить с целями ТЗ, указать аппаратную конфигурацию. Проверить плавность Blender на более тяжёлом скане.
5. Отключить Wi-Fi на 20–30 секунд во время записи, затем подключить. Сравнить число локальных кадров, ACK и файлы на ПК. Проверить остановку с обеих сторон, повтор QR после перезапуска ПК и передачу архива после закрытия приложения.
6. На несколько секунд закрыть объектив, затем продолжить. Проверить, что при потере tracking модель не получает ошибочные наблюдения и на экране видна причина.
7. Проверить QR с Windows Terminal, ручной код, локальный просмотр и экспорт через системное окно Android. Проверить время обработки и температуру в 5–10-минутном сеансе.
8. Установить ZIP на чистый Windows 11 x64 и Blender 4.2 или используемую целевую версию. Проверить раздельно запущенные Scan Engine и Blender, сетевое правило брандмауэра и wheelhouse для установки без интернета.

## Оставшиеся вопросы и следующий выпуск

Реальный RGB-D захват, формат времени на A56, полная задержка, точность реального меша и устойчивость на Windows ещё не измерены. Подготовлены debug APK, ZIP аддона, ZIP движка с Python-скриптами и архив исходников. Сборку Windows EXE и коммерческую подпись APK следует планировать после аппаратной валидации.

Для следующей версии сначала соберите реальные эталонные сеансы и подтвердите регистрацию и масштаб. По результатам измерений настройте пороги и расписание извлечения. Затем добавьте область съёмки для отсечения фона, защищённое спаривание, диагностику дрейфа и интеграцию в Android-проект Phone Rotation при наличии его исходников.
